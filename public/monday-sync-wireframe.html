3. What happens when both sides edit the same field?

Last-write-wins, per field. Every field carries a timestamp. Newer stamp beats older stamp.

Scenario A — No conflict (99% of edits)
Danny updates hours in TableX Scope page at 9:00 AM.
Brian marks the task Done in Monday at 9:15 AM.
Different fields → both edits win. Sync pushes hours to Monday, pulls status to TableX. Done.
Scenario B — Same field, different times
Richie changes a deliverable's status to Review in Monday at 2:00 PM.
Danny changes the same deliverable's status to Done in TableX at 2:03 PM.
Next sync runs at 2:05 PM → Done wins (newer). Review is overwritten. A small toast in TableX says "Richie's earlier Monday edit was overridden." No silent data loss.
Scenario C — "Updated in Monday 2m ago" indicator
Before someone edits a field in TableX, the UI shows a subtle "Updated in Monday 2m ago" badge if Monday's version is newer than what TableX last saw. Encourages a refresh before editing. Prevents most conflicts without needing a heavy locking system.
